# BR：文本锚点扫描正文中的脚本，动态数据页面出现长时间停顿

页面：https://s.shareone.vip/s/sudograph-northwind

## 定位与复现

2026-10-07 使用真实 Chromium / ai-dev-browser 点击、滚轮和 CDP CPU 采样。保留相同的 9 条未解决评论，依次展开订单、展开一条记录的字段、滚轮缩放 6 次。评论含旧 SVG 文本锚点和当前 DOM 文本锚点。

`frontend/src/lib/comments/text-anchoring.ts` 的 `a_segments(document.body)` 遍历全部文本节点，未排除 SCRIPT/STYLE 等非阅读内容。`a_normalizeWithMap` 会为扫描到的每个字符建立映射。`remote-frame-highlighter.ts` 的正文变化监听在 350 ms 后重新定位所存文本评论；`contentSignature()` 同样包含正文脚本的字数。

Sudograph 将完整压缩数据快照内嵌于正文脚本，导致扫描范围约 7.41 百万字符。每次展开改变正文，评论定位反复为数据脚本分配大量字符映射，产生明显的内存回收停顿。

| 同组操作的累计采样 | 修复前 | Sudograph 模板修复后 |
|---|---:|---:|
| 正文文本字符 | 7,409,561 | 145,692 |
| `resolveAnchorInline` + `a_normalizeWithMap` + `a_bestExact` | 2,212 ms | 43 ms |
| 内存回收 | 7,407 ms | 54 ms |

这些是整组操作的 CPU 采样累计值，不是单次交互延迟或跨设备的性能承诺。首次展开的脚本端墙钟时间约 1.2 秒，前后接近；较重的评论定位在布局落地后的延迟任务中发生。初期旧调试浏览器的输入超时不能单独证明应用卡顿，因此未将其作为上述对比证据。

## 已实施的应用侧修复

通用 Sudograph 模板把数据脚本放入 head，正文只保留阅读界面和运行代码；全量记录、评论和锚点协议均保留。不是关闭评论、裁掉数据或修改某张图的专用补丁。应用另外修复了选择文字层遮住 Cytoscape 滚轮输入的问题，并将展开/收起改为明确按钮。

## 建议 ShareOne 的通用修复

1. 文本锚点捕获、位置计算、重定位采用一致的“可阅读文本”遍历，剪掉 SCRIPT、STYLE、NOSCRIPT、TEMPLATE 及自身标注层；避免从代码里找到伪匹配。
2. 同一轮重定位共用文本索引；正文文字或结构真的改变才失效，避免每条评论重复分配整份映射。
3. 增加含大体积正文脚本及多条已失效文本评论的回归用例。展开后文本高亮应重新定位，滚轮/拖动应保持响应；不能以关闭评论作为修复。

## 关于两个 show 的相同警告

同样的“6 comments not shown”在两个 show 出现，本身不能证明视图状态有 bug。旧评论引用 SVG 的 tspan/旧文本位置，当前图使用 DOM 标签；另有被移除的示例角色和已修改的文案，切换 show 不会恢复这些历史目标。它们均可能在两个 show 定位失败。

当前提示仍把“正文锚点不可用”写成“评论未显示”，而评论卡片实际保留在侧栏。此前 BR 已说明这一文案问题。建议区分已知但当前折叠的目标、定位失败的文本锚点，以及应用明确报告 missing 的目标；不要仅凭文本重定位失败断言内容已删除。
